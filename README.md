# Esquilo

Personal finance app for the Brazilian market: automatic expense categorization, cash-flow forecasting, subscription and anomaly detection, and savings insights. Built with LGPD compliance from day one.

> **Status:** Phase 0 — Foundation. Repository conventions and architecture decisions are in place; the backend skeleton is next.

## Repository layout

| Path | Contents |
|---|---|
| `backend/` | ASP.NET Core (.NET 10 LTS) modular monolith. Build configuration only, for now |
| `mobile/` | React Native + Expo + TypeScript app for iOS and Android *(planned)* |
| `infra/` | Terraform, Helm charts and Argo CD manifests *(planned)* |
| `docs/` | [Architecture decision records](docs/adr/README.md) |

## Getting started

Prerequisites: Git and Node.js 20+ (used only for repository tooling).

```bash
npm install   # installs commitlint and husky and activates the git hooks
```

## Workflow

- `main` is protected: every change goes through a pull request and is merged with **squash merge**.
- Commit messages and PR titles follow [Conventional Commits](https://www.conventionalcommits.org/): `type(scope): subject`. The PR title becomes the commit on `main`.
- Versions and changelogs are generated by release-please per component (`api-vX.Y.Z`).
- Branch rules are versioned in [`.github/rulesets/main.json`](.github/rulesets/main.json).

## Conventions

- Line endings are normalized to LF by `.gitattributes` (Windows scripts keep CRLF).
- Code style and analyzer rules live in `.editorconfig` and are enforced at build time.
- Real bank statements and personal data must never be committed. Use `samples/real/` folders, which are git-ignored, for local experiments only.
